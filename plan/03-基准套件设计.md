# plan/03-基准套件设计.md

> 数学论文可验证重放审计器——内置评测基准（模块⑥）设计。
> 版本：v1（2026-10-16，M0 定稿）。

**核心纪律**：真值来源 = 程序化植入（生成器知道错误在第几个公式/哪一行），真值库只存输入与期望，观测运行时实喂引擎实算。

---

## 一、基准设计原则

### 1.1 真值来源纪律

**K17：真值库只存输入与期望，观测运行时实算**

```json
// 真值库条目（data/benchmark/truth.json）
{
  "sample_id": "B001-dimension_mismatch",
  "input_card": {
    "paper_tex": "...",  // 合成论文 LaTeX
    "paper_id": "synth-001"
  },
  "expect": {
    "error_type": "dimension_mismatch",
    "location": "equation-003",
    "is_clean": false,
    "expected_verdict": "invalid"
  },
  // 不存 observed！观测由引擎运行时实算
  "generator_seed": 42,
  "generator_version": "1.0.0"
}
```

**反模式（绝对禁止）**：
- 真值库中出现 `observed` 字段（引擎坏掉也全绿的假门）
- 真值库中存"引擎算好的答案"（冻结的是观测，不是输入+期望）

### 1.2 植入错误五类白名单

| 错误类型 | 错误码 | 描述 | 植入方式 |
|---|---|---|---|
| 量纲不一致 | `dimension_mismatch` | 公式左右量纲不等 | 在等式一侧乘/除一个带量纲的常数 |
| 符号推导非法步 | `illegal_derivation` | 推导链中某步不合法 | 在推导链中插入一个非法等价变换 |
| 数值断言算错 | `numeric_mismatch` | 数值表/算例结果错误 | 在数值表中偏移一个值 |
| label·ref 悬空 | `dangling_ref` | 引用了不存在的 label | 删除一个被引用的 label |
| 定理依赖断链 | `dep_chain_break` | 定理依赖链断裂 | 删除一个中间引理 |

**K18：覆盖度分母反射自代码常量**

```python
# data/benchmark/manifest.json
ERROR_TYPES = [
    "dimension_mismatch",
    "illegal_derivation",
    "numeric_mismatch",
    "dangling_ref",
    "dep_chain_break",
]
MIN_COVERAGE = {
    "dimension_mismatch": 3,   # 最低覆盖项数
    "illegal_derivation": 3,
    "numeric_mismatch": 3,
    "dangling_ref": 3,
    "dep_chain_break": 3,
}
```

- 覆盖度分母 = `sum(MIN_COVERAGE.values())`
- 新增错误类型无用例 → 生成器直接报错（堵死"悄悄做小分母"）

### 1.3 误报率 0 优先

**K19：误报率 0 优先**

- 干净论文被判为有问题 = 最坏失败模式
- 样本驱动层误报率须实测
- 无观测通道层由 manifest 显式声明未测

## 二、合成论文 LaTeX 生成器

### 2.1 生成器架构

```

├── generator/
│   ├── __init__.py
│   ├── paper_template.py      # 论文骨架模板
│   ├── error_injector.py      # 错误植入器
│   ├── truth_builder.py       # 真值构建器
│   └── deterministic_rng.py   # 确定性 RNG（splitmix64）
├── truth.json                 # 真值台账
├── manifest.json              # 覆盖度口径
├── samples/                   # 合成论文 .tex 文件
│   ├── B001-dimension_mismatch/
│   ├── B002-illegal_derivation/
│   ├── B003-numeric_mismatch/
│   ├── B004-dangling_ref/
│   ├── B005-dep_chain_break/
│   └── C001-clean/            # 干净论文（误报率验证）
└── snapshots/                 # 预置模型输出快照
```

### 2.2 确定性生成纪律

**K20：确定性生成**

- 禁 stdlib `random`（不承诺跨版本序列一致）
- 禁 set 迭代序
- 禁系统时钟
- 自研确定性 RNG（splitmix64）
- 落盘产物无时间戳
- 两次运行/构建逐字节一致
- 配"再生成位级一致"守门测试

**K21：zip 容器字节跨平台冻结**

- 生成器一律 `ZIP_STORED` + `create_system=0` + `external_attr` 常量
- "任意平台重生成位级一致"才无例外

## 三、真实论文回归集

### 3.1 定位

- 只作"不误报"的负样本（干净论文）与少量有公开勘误的正样本
- 只存元数据（arXiv id、版本、勘误说明引用）与本地解析结果
- **不随仓分发全文**

### 3.2 入库格式

```json
{
  "paper_id": "arXiv:XXXX.XXXXX",
  "version": 1,
  "source": "arXiv",
  "has_erratum": false,
  "erratum_url": null,
  "local_parse_sha256": "...",
  "is_clean": true,
  "notes": "用于验证误报率 0"
}
```

### 3.3 获取流程

1. 用户本地执行 `python -m auditor fetch --arxiv-id XXXX.XXXXX`
2. 下载 arXiv e-print gzip 包
3. 本地解析，生成解析结果
4. 解析结果 sha256 登记进 `data/real_papers/registry.json`
5. **原文不入仓**

## 五、指标计算

### 5.1 核心指标

| 指标 | 计算方式 | 目标 |
|---|---|---|
| 检出率 | 正确检出的错误数 / 总错误数 | ≥ 95% |
| 误报率 | 干净论文被判有问题数 / 总干净论文数 | **0** |
| 解析覆盖率 | 已识别结构数 / 总结构数 | 如实报告 |
| 复算一致率 | 数值复算一致的断言数 / 总数值断言数 | 如实报告 |
| 依赖图完整率 | 无悬空引用的论文数 / 总论文数 | 如实报告 |

### 5.2 指标派生

- 所有指标从真值库 + 引擎输出派生
- 不手算、不硬编码
- 测试中锁死"指标计算函数与真值库联动"

## 六、探活机制

### 6.1 探活定义

**K22：探活断言"坏实现被判未达标"**

- 故意弄坏被测行为 → 门必须变红
- 弄坏后仍绿 = 假门

### 6.2 探活用例

```python
def test_benchmark_probe():
    """探活：故意注入一个错误，引擎必须检出"""
    # 1. 从真值库取一个含 dimension_mismatch 的样本
    sample = load_sample("B001-dimension_mismatch")
    # 2. 运行引擎
    result = engine.audit(sample)
    # 3. 断言 verdict != ok
    assert result.verdict != "ok"
    # 4. 断言 error_type == "dimension_mismatch"
    assert result.error_type == "dimension_mismatch"

def test_benchmark_false_positive_probe():
    """探活：干净论文必须不被误报"""
    sample = load_sample("C001-clean")
    result = engine.audit(sample)
    assert result.verdict == "ok"

def test_benchmark_gate_broken():
    """探活：故意破坏引擎，门必须变红"""
    # 1. 临时修改引擎，使其总是返回 ok
    original_audit = Engine.audit
    Engine.audit = lambda self, sample: AuditResult(verdict="ok")
    try:
        # 2. 运行探活
        sample = load_sample("B001-dimension_mismatch")
        result = Engine.audit(sample)
        # 3. 断言失败（因为引擎被破坏）
        assert result.verdict != "ok"  # 这会失败，证明探活有效
    finally:
        Engine.audit = original_audit
```

### 6.3 探活位置

- 探活打在**消费处**的导入引用，打定义处不生效
- 每个错误类型至少一个探活用例

## 八、基准 runner

### 8.1 Runner 接口

```python
# benchmark/runner.py
def run_benchmark(
    benchmark_dir: str,
    only: Optional[List[str]] = None,  # 只跑特定错误类型
    verbose: bool = False
) -> BenchmarkResult:
    """
    运行基准套件
    - 加载真值库
    - 对每个样本运行引擎
    - 计算指标
    - 返回结果
    """
```

### 8.2 退出码语义

| 退出码 | 含义 |
|---|---|
| 0 | 基准全绿（所有指标达标） |
| 1 | 基准未达标（有指标不达标） |
| 2 | 用法错误（基准目录不存在、配置错误） |

### 8.3 `--only` 白名单

```bash
python -m auditor bench --only dimension_mismatch,numeric_mismatch
```

- `--only` 白名单 = `ERROR_TYPES` 常量
- 传入不在白名单中的类型 → exit 2
