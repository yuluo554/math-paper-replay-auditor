## 一、依赖分层（extras）

### 1.1 extras 设计

```toml
# pyproject.toml
[project.optional-dependencies]
core = [
    "sympy>=1.12",
    "mpmath>=1.3",
    "pydantic>=2.0",
]
dev = [
    "pytest>=7.0",
    "pytest-cov>=4.0",
    "ruff>=0.1.0",
]
gui = [
    "PySide6>=6.6.3.1,<6.7",  # 3.8 上限
]
build = [
    "PyInstaller>=6.22.3",
    "setuptools<81",  # 3.8 兼容
]
report = [
    # 报告导出（可选，当前版本暂不引入）
]
all = [
    "auditor[core,dev,gui,build]",
]
```

### 1.2 extras 纪律

**K33：extras 一律不得进入运行时必需面**

- `core` = 运行时必需（审计核心零模型可跑）
- `dev` = 开发期必需（测试、lint）
- `gui` = GUI 必需（PySide6）
- `build` = 打包必需（PyInstaller）
- `report` = 报告导出（可选）

**K34：测试期 import 的库必须进 dev extra**

- 测试中 import 的每个库，都必须在 `dev` extra 中
- 干净环境 `pip install -e ".[dev]"` 后，`pytest` 必须全绿

**K35：README 安装行与 CI 全部跑测试的 job 用同一 extras 集合**

- README 快速开始：`pip install -e ".[dev,core]"`
- CI test job：`pip install -e ".[dev,core]"`
- 收集数一致

## 二、打包白名单

### 2.1 数据内嵌白名单

```
packaging/DATAS_WHITELIST.json
{
  "version": "1.0.0",
  "entries": [
    {"source": "data/benchmark/truth.json", "target": "data/", "type": "file"},
    {"source": "data/benchmark/manifest.json", "target": "data/", "type": "file"},
    {"source": "data/benchmark/samples/", "target": "data/samples/", "type": "dir"},
    {"source": "data/benchmark/snapshots/", "target": "data/snapshots/", "type": "dir"},
    {"source": "data/real_papers/registry.json", "target": "data/", "type": "file"},
    {"source": "data/knowledge/", "target": "data/knowledge/", "type": "dir"}
  ],
  "excluded": [
    "data/**/_private/",
    "data/**/raw/",
    "data/**/*.pdf"
  ]
}
```

### 2.2 打包纪律

**K36：白名单单一事实源**

- datas 只准由 `packaging.build_datas()` 产生
- 复制禁区段（版权原文 raw/）在构建器内直接抛错
- 构建后遍历断言（dist 无禁区成分 + 内嵌数据与仓库逐份对账）

**K37：目录条目与文件条目的目标目录算法必须分档**

- 文件取父目录
- 目录取条目自身
- 测试断言"包内路径 == 仓库内相对路径"

**K38：入包集合 == 白名单（双向对账）**

- 正向：白名单每份都在包内（防漏拷）
- 反向：包内数据集合与白名单恰好相等（防多）
- 逐份核内嵌数据 sha256 与仓库冻结件一致

## 三、双 exe 打包

### 3.1 双 exe 分工

| exe | 名称 | console | 用途 |
|---|---|---|---|
| CLI | `auditor-cli.exe` | True | 脚本化验证通路（selfcheck/bench/check） |
| GUI | `auditor.exe` | False | 桌面应用 |

### 3.2 PyInstaller spec 分档

**K39：两个打包目标的 hiddenimports/excludes 必须按目标分档**

- GUI 专属重件只进 GUI 目标
- CLI 目标显式 `excludes` 掉 Qt 栈
- CLI 体积目标：< 20MB

### 3.3 冻结入口

**K40：冻结入口必须是"绝对导入的薄模块"**

```python
# cli_entry.py（薄入口，绝对导入）
import sys
from auditor.cli import main

if __name__ == "__main__":
    sys.exit(main())
```

- 入口文件无相对导入
- 入口文件有 `__main__`
- 回归 = AST 静态断言（扫入口及其调用链禁止 `ImportFrom` 的 `level>0`）

### 3.4 窗口 exe 对未知参数报错

**K41：窗口版对未知参数 exit 2（不静默忽略）**

- 入口先挑出无法识别的参数 → 打印用法 + exit 2
- 回归测试打桩 `run_gui`，防挂死

### 3.5 冻结态自检

**K42：exe --selftest 内建参数**

```bash
auditor.exe --selftest in.json out.txt
```

- 内嵌数据定位 + calc 全链路 + 内置基准 + GUI offscreen 冒烟
- 结论写文件回传、退出码携带成败
- 自检 JSON 断言 `frozen=true` + `data_dir` 落在 dist 内

## 四、脱敏四步

### 4.1 脱敏检查清单

```bash
# Step 1: 全历史 blob 扫描
git rev-list --all | while read c; do git grep -lE "\.env$|\key$|secret|token" "$c" 2>/dev/null; done

# Step 2: 内容级扫描
git grep -E "sk-|1[3-9]\d{9}|\d{17}[\dXx]|C:\\Users|\\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\\.[A-Za-z]{2,}\b"

# Step 3: 二进制样例扫描
# 用 zipfile 扫描 docx 等 zip 型产物

# Step 4: 提交元数据邮箱
git log --format="%ae %ce" --all | sort -u
```

### 4.2 脱敏纪律

**K43：HANDOFF 库内写相对路径**

- 用法行写 `plan/HANDOFF-Mx.md`，不写 `D:\...\plan\HANDOFF-Mx.md`
- 过脱敏自查

**K44：留档只写类别与实算来源，不写词面值**

- 邮箱数字串从 `git log --format=%ae %ce --all` 实算
- 用户名从 `getpass.getuser()` 实算
- 留档只写"类别 + 实算来源"

**K45：姊妹项目表述用方向级描述**

- 不写具体领域名词（"结构/脚手架/招投标文书"）
- 写"工程技术类/财务合规类"

## 七、干净环境验证

### 7.1 验证流程

```bash
# 1. 全新 clone
git clone https://github.com/<u>/math-paper-replay-auditor.git /tmp/verify
cd /tmp/verify

# 2. 全新 venv
py -3.12 -m venv .venv
.\.venv\Scripts\activate
python -m pip install -U pip setuptools wheel

# 3. 按 README 安装
python -m pip install -e ".[dev,core]"

# 4. 逐条跑 README 命令
python -m auditor selftest
python -m auditor bench
python -m auditor audit --input data/benchmark/samples/B001-dimension_mismatch/paper.tex

# 5. 全量测试
python -m pytest tests/ -v --tb=short

# 6. 收集数对账
pytest --collect-only -q | wc -l  # 与 README 声明一致
```
