## 一、LaTeX 源码摄入与结构解析（模块①）

### 1.1 输入输出契约

- **输入**：arXiv e-print 整包（gzip）或本地 `.tex` 项目目录
- **输出**：论文结构树（JSON）
  ```json
  {
    "paper_id": "arXiv:XXXX.XXXXX",
    "sections": [...],
    "equations": [...],
    "theorems": [...],
    "lemmas": [...],
    "proofs": [...],
    "tables": [...],
    "refs": [...],
    "labels": [...],
    "packages": [...],
    "unrecognized_envs": [...],
    "unrecognized_macros": [...],
    "coverage": { "total": N, "recognized": N, "unrecognized": N }
  }
  ```

### 1.2 解析引擎：确定性 LaTeX 解析器（零模型）

**核心策略**：正则 + 上下文无关文法片段 + 栈式环境追踪。

**解析流程**：
1. **预处理**：UTF-8 读取 → 行尾归一（LF）→ 注释剥离（`%` 到行尾，但保留 `\%`）
2. **主文件定位**：找 `\documentclass` 所在文件；递归解析 `\input`/\`include`/\`subfile`
3. **宏包收集**：`\usepackage` 与 `\documentclass` 选项登记
4. **环境栈追踪**：维护 `\begin{env}` → `\end{env}` 栈，检测嵌套与未闭合
5. **结构提取**：
   - `\section*`/\`subsection*` 等 → section 节点
   - `\begin{equation}`/\`align`/\`gather` 等 → equation 节点
   - `\begin{theorem}`/\`lemma`/\`proposition`/\`corollary` → theorem 节点
   - `\begin{proof}` → proof 节点
   - `\begin{table}`/\`tabular` → table 节点
   - `\label{...}` → label 节点（挂到最近环境）
   - `\ref{...}`/\`eqref{...}`/\`cite{...}` → ref 节点
6. **未覆盖清单**：所有未识别的 `\begin{...}` 环境与 `\...` 宏登记进 `unrecognized_envs`/`unrecognized_macros`，**不得静默丢弃**

**K1：解析覆盖率报告**
- 分母 = 所有 `\begin{env}` 出现次数 + 所有 `\command` 出现次数
- 分子 = 已识别的次数
- 覆盖率 = 分子/分母，必须如实报告（不得虚高）

**K2：未覆盖清单不得静默丢弃**
- 未识别环境/宏一律登记进 `unrecognized_envs`/`unrecognized_macros` 数组
- 下游引擎必须看到这个清单，不得把"没解析到"当成"论文里没有"

**K3：自定义宏需显式声明映射**
- 提供 `macro_map.json` 让用户声明 `\mydef` → 标准宏的映射
- 未声明的自定义宏不参与重放（标记 `unmapped_macro`）

### 1.3 模型辅助归一化（可选，默认关闭）

- 开关：`--with-llm-normalize`
- 仅对 `unrecognized_envs` 与 `unrecognized_macros` 做归一化建议
- 归一化结果必须经用户确认才进入主路径
- **默认关闭**：审计核心零模型可跑

## 二、符号断言重放（模块②）

### 2.1 输入输出契约

- **输入**：模块①结构树中的可符号化断言（等式/不等式/极限/求和/积分/递推）
- **输出**：逐条 verdict
  ```json
  {
    "claim_id": "eq-001",
    "claim_type": "equality",
    "steps": [
      {"expr": "...", "rule": "...", "valid": true},
      {"expr": "...", "rule": "...", "valid": false, "counterexample": "..."}
    ],
    "verdict": "ok" | "invalid" | "undecidable",
    "evidence": "..."
  }
  ```

### 2.2 引擎：SymPy 重演推导链

**核心策略**：将 LaTeX 公式转为 SymPy 表达式，逐步验证相邻步的等价性/合法性。

**转换流程**：
1. LaTeX → SymPy：使用 `sympy.parsing.latex.parse_latex`
   - 注意：`parse_latex` 覆盖度有限，未识别部分登记进 `unparsed_exprs`
2. 推导链重建：
   - 等式：`A = B = C = ...` → 拆分为 `A == B`, `B == C`, ...
   - 不等式：`A < B < C` → `A < B`, `B < C`
   - 极限：`lim_{x→a} f(x) = L` → 验证 `limit(f, x, a) == L`
   - 求和：`Σ_{i=a}^{b} f(i) = S` → 验证 `summation(f, (i, a, b)) == S`
   - 积分：`∫_{a}^{b} f(x)dx = I` → 验证 `integrate(f, (x, a, b)) == I`
   - 递推：`a_{n+1} = f(a_n)` → 验证前若干项
3. 逐步验证：
   - 等价性：`sympy.simplify(A - B) == 0`
   - 合法性：检查每步变换是否属于合法规则集（代数恒等变换、三角恒等式、微积分基本定理等）

**K4：undecidable 与 invalid 必须分级**
- `invalid`：引擎确证错误（`simplify(A - B) != 0` 且非数值近似）
- `undecidable`：引擎能力外（如涉及未定义函数、超越方程无解析解、自定义宏未映射）
- **不得虚高判定**：`undecidable` 不得报告为 `ok`

**K5：每类断言登记能力覆盖度**
- 按断言类型（equality/inequality/limit/sum/integral/recurrence）分别统计
- 覆盖度 = 已处理数 / 总断言数
- 未覆盖类型显式列出

**K6：重放必须可复跑**
- 同输入同结论：固定 seed + 确定性算法
- 测试中锁死"双跑逐字节一致"

## 三、数值断言复算（模块③）

### 3.1 输入输出契约

- **输入**：论文数值表、算例、参数点
- **输出**：独立重算结果 vs 论文所报数值
  ```json
  {
    "claim_id": "num-001",
    "claim_type": "table_value",
    "paper_value": 3.14159,
    "recomputed_value": 3.1415926535,
    "tolerance": 1e-6,
    "deviation": 2.6535e-6,
    "verdict": "consistent" | "inconsistent" | "uncomputable",
    "evidence": "..."
  }
  ```

### 3.2 引擎：与符号路径实现独立的数值重算路径

**核心策略**：数值断言一律走独立重算路径，不依赖符号路径的自证。

**独立路径实现**：
- 符号路径：SymPy 精确计算（有理数/符号）
- 数值路径：`decimal` 高精度 + `mpmath` 任意精度浮点
- 两条路径**不共享核心函数**：
  - 符号路径用 `sympy.nsimplify` 做数值→符号
  - 数值路径用 `mpmath.mpf` 做纯数值计算
  - 两条路径的入口函数不同，测试中锁死"不共享核心函数"

**K7：数值口径单一定义点（落 plan/02 唯一定义点）**

```python
# plan/02 中定义，代码中 import 使用
NUMERICAL_TOLERANCE = {
    "default": 1e-6,        # 默认容差
    "table_value": 1e-4,    # 表格数值
    "convergence": 1e-8,    # 收敛性判定
    "integral": 1e-6,       # 数值积分
    "series": 1e-8,         # 级数求和
}
```

- 守门断言：扫描代码中除 `NUMERICAL_TOLERANCE` 外是否出现硬编码容差值
- 注记文本与算法同源：报告中的容差说明从 `NUMERICAL_TOLERANCE` 派生

**K8：数值断言不采信符号路径的自证**
- 数值路径必须独立实现
- 测试中锁死"两条路径不共享核心函数"

**K9：容差与数值口径一处定义**
- 唯一定义点 = `NUMERICAL_TOLERANCE` 字典
- 扫描面：引擎/基准/测试源码（含 docstring/注释）
- 出现硬编码容差值（如 `1e-6`、`0.0001`）即红

## 四、量纲一致性审计（模块④）

### 4.1 输入输出契约

- **输入**：物理/工程类论文的公式（符号 + 单位标注）
- **输出**：每条公式的量纲平衡判定
  ```json
  {
    "claim_id": "dim-001",
    "formula": "F = ma",
    "lhs_dimension": "[M][L][T]^{-2}",
    "rhs_dimensions": ["[M]", "[L][T]^{-2}"],
    "balanced": true | false | null,
    "evidence": "...",
    "note": "..."
  }
  ```

### 4.2 引擎：确定性量纲代数（单位向量运算）

**核心策略**：将物理量表示为基向量上的指数向量，做向量加法。

**基本量纲基**：`[M]`（质量）、`[L]`（长度）、`[T]`（时间）、`[I]`（电流）、`[Θ]`（温度）、`[N]`（物质的量）、`[J]`（发光强度）

**量纲向量**：每个物理量映射为 7 维向量，如 `[v] = [L][T]^{-1}` → `(0, 1, -1, 0, 0, 0, 0)`

**运算规则**：
- 乘法：向量相加
- 除法：向量相减
- 幂：向量乘标量
- 加法/减法：向量必须相等
- 等式：左右向量必须相等

**K10：论文未标单位时不猜测**
- 未标单位 → `balanced = null`（即 `undecidable`）
- 报告必须说明"缺单位标注"
- **不得猜测单位**

**K11：量纲不平衡是强证据，量纲平衡不等于公式正确**
- 量纲不平衡 → `balanced = false`，确证公式有误
- 量纲平衡 → `balanced = true`，但报告必须声明"量纲平衡不等于公式正确"
- 边界声明写进报告模板

**K12：量纲代数确定性**
- 纯整数向量运算，无浮点误差
- 同输入同结论

## 五、定理依赖图完整性（模块⑤）

### 5.1 输入输出契约

- **输入**：模块①的 label / ref / 定理-引理-证明结构
- **输出**：依赖图分析结果
  ```json
  {
    "dangling_refs": [
      {"ref": "thm:nonexistent", "location": "sec-3", "message": "引用了不存在的 label"}
    ],
    "ghost_labels": [
      {"label": "lem:unused", "location": "sec-2", "message": "从未被引用的定理"}
    ],
    "broken_chains": [
      {"from": "thm:main", "via": "lem:missing", "to": "cor:result", "message": "依赖断链"}
    ],
    "dependency_graph": { "nodes": [...], "edges": [...] },
    "topology": { "acyclic": true, "cycles": [] }
  }
  ```

### 5.2 引擎：确定性图算法

**核心策略**：构建有向图，做可达性分析与拓扑排序。

**算法**：
1. 节点：所有 `label`（定理/引理/证明/方程）
2. 边：`\ref{L}` → `L`（依赖方向：引用者 → 被引用者）
3. 悬空引用：`ref` 指向的 `label` 不存在
4. 幽灵 label：`label` 从未被任何 `ref` 引用
5. 依赖断链：`A → B → C` 中 `B` 不存在
6. 拓扑检测：检测循环依赖

**K13：编号重排/引用对账可复跑且一致**
- 确定性算法，同输入同输出
- 测试中锁死"双跑逐字节一致"

**K14：幽灵 label 仅为提示**
- 论文可不引用某引理 → 幽灵 label 是"结构性可疑"，不是"确证问题"
- 报告必须区分"结构性可疑"与"确证问题"

## 六、三级判定语义（跨模块共用）

### 6.1 判定词汇表（协议、代码、文档三处同源）

| 判定 | 含义 | 使用条件 |
|---|---|---|
| `ok` | 通过 | 引擎确证正确 |
| `invalid` | 确证错误 | 引擎确证错误（附最小反例） |
| `undecidable` | 无法判定 | 引擎能力外 / 缺标注 / 未映射宏 |

**K15：三态判定词汇三处同源**
- 协议文档：本文
- 代码常量：`VERDICTS = {"ok", "invalid", "undecidable"}`
- 结构测试：判定只追加 verdict 三字段、不改扫描输出的位置/条数/顺序
- 文档里出现第四态词面即测试红

**K16：降级路径 off/failed → 全 undecidable + meta 显式声明**
- 引擎不可用时，所有判定降级为 `undecidable`
- meta 字段显式声明降级原因
