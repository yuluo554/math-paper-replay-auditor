## 一、测试分层

### 1.1 分层架构

```
Layer 1: 单元测试（tests/unit/）
  - 每个模块独立测试
  - mock 外部依赖
  - 覆盖率目标：≥ 80%

Layer 2: 集成测试（tests/integration/）
  - 模块间交互测试
  - 解析 → 重放 → 报告 全链路
  - 使用合成论文样本

Layer 3: 基准测试（tests/benchmark/）
  - 基准 runner 端到端
  - 探活用例
  - 指标达标验证

Layer 4: 守门测试（tests/gate/）
  - K 编号口径守门
  - 确定性守门
  - 编码守门
  - 安装面守门

Layer 5: 端到端测试（tests/e2e/）
  - CLI 完整流程
  - 真实论文回归集（本地）
  - 干净环境验证
```

### 1.2 测试计数纪律

**K23：测试计数全仓一致**

- `pytest --collect-only -q` 的收集数必须与 README 中声明的测试数一致
- 新增测试文件必须同步更新 README 与 CI workflow
- 测试计数当轮实测，不抄上一棒

## 二、退出码语义

### 2.1 CLI 退出码

| 退出码 | 语义 | 使用场景 |
|---|---|---|
| 0 | 达标 | 审计完成，无问题检出 |
| 1 | 未达标 | 审计完成，检出问题 |
| 2 | 用法错误 | 参数错误、文件不存在、格式错误 |
| 3 | 缺依赖 | 模型开关开启但模型不可达、GUI 缺 PySide6 |

### 2.2 退出码锁进测试

**K24：退出码三语义锁进测试**

```python
def test_cli_exit_codes():
    """退出码语义测试"""
    # 0 = 达标
    result = run_cli(["audit", "--input", "clean_paper.tex"])
    assert result.exit_code == 0

    # 1 = 未达标
    result = run_cli(["audit", "--input", "error_paper.tex"])
    assert result.exit_code == 1

    # 2 = 用法错误
    result = run_cli(["audit", "--input", "nonexistent.tex"])
    assert result.exit_code == 2

    # 3 = 缺依赖
    result = run_cli(["audit", "--with-llm", "--input", "paper.tex"])
    # 模型不可达时 exit 3
    assert result.exit_code == 3
```

### 2.3 退出码不混用

**K25：形态失败与行级失败给不同退出码**

- 形态失败（文件不存在、坏格式、空文件）→ exit 2，不进逐行清单
- 行级失败（某条断言有问题）→ exit 1，逐条进异常清单

## 二之二、桌面形态验收（v0.1.1 新增）

> v0.1.0 的 `auditor.exe` 是占位空窗口，而测试全绿——因为没有任何测试触碰 GUI。
> 以下三层把"死壳"堵死（preflight ㉕）。

**形态四格（delivery-forms §零）**：

| 形态 | 主入口 | 主控件/命令 | 接到哪个业务函数 | 断言在哪条测试 | 产物在哪个附件 |
|---|---|---|---|---|---|
| CLI | `auditor` / `python -m auditor` | `audit` / `bench` / `selftest` | `pipeline.audit_paper` | `tests/benchmark/*`、`tests/gate/*` | `auditor-cli.exe` |
| 桌面应用 | `auditor.exe` / `python -m auditor.gui.main_window` | 路径输入 / 浏览 / 开始审计 / 导出报告 | `gui.pipelines.audit_paper` / `export_all` | `tests/test_gui_controller.py` 13 条 | `auditor.exe` |

**三层验收**：

| 层 | 验什么 | 落点 |
|---|---|---|
| 控制器层 | 干净论文零误报 / 含错论文必检出 / 缺输入报错不崩 / 三格式导出 / HTML 0 外链 / JSON 往返 | `TestController`（7 条） |
| 接线层 | 三个按钮（浏览/审计/导出）真实 `connect`；窗口调 `pipelines`；入口用真窗口而非占位；`--selftest` 不 import Qt | `TestWindowWiring`（4 条，AST） |
| 打包层 | `auditor.gui.window/pipelines` 在 hiddenimports；demo GIF 存在 | `TestPackaging`（2 条） |

**依赖缺失语义**：缺 PySide6 时窗口 exit 3；`--selftest` 走零 Qt 路径仍可跑。

## 四、失败路径测试

### 4.1 必须覆盖的失败路径

| 失败场景 | 预期行为 | 退出码 |
|---|---|---|
| 输入文件不存在 | 报错 + exit 2 | 2 |
| 输入文件格式错误 | 报错 + exit 2 | 2 |
| 输入文件为空 | 报错 + exit 2 | 2 |
| 输入文件非 UTF-8 | 报错 + exit 2 | 2 |
| 模型开关开启但不可达 | 报错 + exit 3 | 3 |
| 解析覆盖率 < 100% | 如实报告 + 不静默 | 0/1 |
| 数值复算不一致 | 报告不一致 + exit 1 | 1 |
| 量纲不平衡 | 报告 + exit 1 | 1 |
| 悬空引用 | 报告 + exit 1 | 1 |

### 4.2 失败隔离

**K30：单件异常不中断整批**

```python
def test_batch_failure_isolation():
    """批量处理中单件异常不中断整批"""
    papers = ["good1.tex", "bad.tex", "good2.tex"]
    results = []
    for paper in papers:
        try:
            results.append(engine.audit(paper))
        except Exception as e:
            results.append(AuditResult(verdict="undecidable", error=str(e)))
```

## 五、变异验证

### 5.1 守门必须证伪

**K31：新增/改写的守门要做变异验证**

```python
def test_k7_gate_mutation():
    """变异验证：故意注入硬编码容差，门必须变红"""
    # 1. 临时修改源码，注入硬编码容差
    inject_hardcoded_tolerance()
    # 2. 运行守门测试
```

### 5.2 三个"做了但没验"的无效形态

| 形态 | 描述 | 正解 |
|---|---|---|
| 阴性样本不含针 | 样本靠前缀被排除，待测逻辑空转 | 先断言样本中确实含待测形态 |
| 对照组改"测试的存在形式" | 改函数名移出收集集 | 改被断言的行为 |
| 断言张冠李戴 | `assert "xxx" in source` 证明不了函数被调用 | "我要验的是 X，断言里就只准出现 X" |

## 七、M6 补强守门（K50–K54）

> **M6 审查结论**：M1–M5 的守门体系有一个**结构性盲区**——128 个守门测试
> 从未断言"检出率"。真值库的五类植入错误中，四类因**植入器静默空转**
> （锚点与模板不匹配，返回原文）而从未真正进入样本；引擎侧也从未真算
> （数值引擎拿报告值与自身比较、图引擎断链检测恒返回空）。
> 结果：M5 声称"引擎可用"时，基准实际只对 1/5 类错误有效（检出率 20%），
> 而 128 个测试全绿。以下五条守门即针对该盲区补强。

### 7.1 检出率与错误类型归属

**K50：基准检出率与错误类型归属必须被断言**

- 检出率 ≥ 95%（真值库全量实跑，非构造样本）
- 逐样本点名：每个错误样本都必须判 `invalid`（差异落到具体样本）
- 每类错误检出数须达 manifest 的 `min_required`
- **错误类型归属核对**：检出的 `error_type` 必须与真值一致——
  只查"是否判 invalid"会被"任意一类错误一律命中"蒙混过关
- 错误样本的上游断言不得整片 `undecidable`

守门：`tests/gate/test_k50_detection_rate.py`

**K51：检出率守门本身必须可证伪**

- 让重放引擎对不等价步一律放行 → 检出率门必须变红
- 让数值路径求值恒定失败 → `numeric_mismatch` 必须漏检
- 关掉悬空引用检测 → `dangling_ref` 必须漏检
- 注入器静默空转（返回原文）→ 必须抛 `ValueError`

守门：`tests/gate/test_k50_detection_rate.py`（K51 诸例）

> M6 实测：把 `_verify_equality_chain` 换成"一律放行"后检出率由 100% 降至 80%、
> `passed=False`——守门确实可证伪；恢复后回到 100%。

### 7.2 冻结态与源码态对账

**K52：冻结产物与源码态结论必须逐项一致**

- 冻结 `bench` 的关键指标行必须与源码态**完全相同**
- 冻结态必须逐类检出（防"总体通过"掩盖某类归零）
- 冻结态 `selftest` 必须 exit 0

守门：`tests/gate/test_k52_frozen_parity.py`（产物不存在时显式 skip，不假装通过）

> 本条来自 M6 实测的真实缺陷：`sympy.parse_latex` 的 ANTLR 后端在打包时
> 因动态 import 被 PyInstaller 漏收，**静默返回 None**（不抛异常），
> 使冻结态 `illegal_derivation` 归零（80% vs 源码态 100%）。

### 7.3 运行时前提与指令面

**K53：sympy LaTeX 解析器的运行时前提必须可满足**

- pyproject 对 `antlr4-python3-runtime` 的上界必须收在 4.11.x
- 当前环境 `parse_latex` 必须真的能解析（非"能 import 就算过"）
- 解析全失败必须落 `undecidable`，不得伪造成 `ok`

守门：`tests/gate/test_k53_latex_runtime.py`

**K54：audit 编排链与报告双轨必须真实可用**

- 审计不存在的路径必须 exit 2（不是"跑通返回 0"）
- 干净论文 exit 0 / 含确证问题 exit 1
- 人读与机读报告内容同源一致、机读逐字节可复现、零外链
- `selftest` 必须可证伪（数据不可达时返回 False）

守门：`tests/gate/test_k54_audit_pipeline.py`

> 本条来自 M6 实测：`pipeline.audit_paper()` 与 `selftest()` 曾是
> `return 0` / `return True` 的空壳，README 头号功能对不存在路径也返回 0。
